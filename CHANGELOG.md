# Changelog

## 0.2.0 (2026-11-21)

- Optional `f32` numeric mode (`compile --numeric`, spec §14): `f32` loads/stores are
  emitted with `bitcast` and `f32` add/sub/mul are lowered under a numeric contract
  (ULP <= 4, or relative/absolute error <= 1e-6; non-finite values must match bitwise).
  Exact mode is unchanged and still refuses `f32` arithmetic. The first measurement at
  n = 65536 is 1.15x slower than the CPU, so the f32 cost gate still needs calibration
  before this becomes a default opportunity.
- Two correctness fixes for loops whose induction starts at a parameter. The runtime now
  treats the start and the bound as element indices (not byte addresses) when computing
  upload/readback ranges, so the tail of the written region is copied back and reads are
  uploaded in full; previously such kernels silently lost GPU writes beyond the first
  alignment block. The emitted statements also use the batched index, so trips above the
  65535-workgroup limit no longer rewrite the first batch's addresses. Measured on a
  step-2, 10,000,000-element loop: memory matches word-for-word and the GPU is 2.31x
  faster (same-address load/store variant 1.48x).
- Kernels are no longer capped by wgpu's 65535-workgroups-per-dimension limit: the generated
  shader walks the trip in stride-sized batches and the host clamps the dispatch count. A
  32-multiply loop with 5,000,000 elements now runs correctly (7.7x faster than the CPU on the
  M2 measurement) where it previously failed validation above 4,194,240 elements. Only the WGSL
  text changes; manifests and the rewritten module stay byte-identical.
- CI and local development now pin one compiler (`rust-toolchain.toml`, 1.98.1, the
  workspace minimum). On a newer `stable` the thin binary's `unused_crate_dependencies`
  expectation becomes unfulfilled and `-D warnings` fails, so the hosted runner and the
  developer machine have to agree on the toolchain.
- CI installs a software Vulkan driver (lavapipe) so the GPU correctness tests run on hosted
  runners instead of failing for the lack of an adapter; only the five benchmark-style
  comparisons are skipped there, because a software device says nothing about GPU/CPU speed.
- The wgpu dependency now enables the Vulkan backend alongside Metal. A metal-only build has
  no graphics backend at all on Linux: creating an instance panics and the released Linux
  binary could not use the GPU. With Vulkan enabled the Linux build can reach the device.
  Hosted CI runners have no adapter, so the eleven tests that build one are skipped by name
  there (five in the WGSL crate, six in the runtime crate); the format check also left CI
  because the public mirror is generated by stripping comments and is not rustfmt-clean by
  construction. Formatting stays a local gate.
- GitHub Actions now run on every push and pull request: formatting, clippy with warnings
  denied, the workspace test suite (the five tests that need a real GPU device are skipped
  explicitly on hosted runners) and the corpus evaluation with its Gate 1 verdict. A release
  workflow builds Linux x86-64 and macOS arm64/x86-64 archives with checksums on tag pushes and
  attaches them to the GitHub Release; a manual run builds those archives without publishing.
  The README gained the CI badge and an install section pointing at the release assets.
- Address recovery and the effects proof obligation no longer rescan the whole function body
  per loop: both now build a per-function candidate index (memory-access values and
  side-effecting operators respectively) and walk only loop members. Compile time: Draco decoder
  0.120s to 0.107s, Basis transcoder 0.0756s to 0.0535s (29% faster), mappings 0.021s to
  0.016s. Artifacts and stdout are byte-identical on all corpus inputs.
- Planning caches each function's side-effect and store facts once (per block) instead of
  re-scanning every value of the function for every loop. Compile time: Draco decoder
  0.141s to 0.116s (18% faster), Basis transcoder 0.100s to 0.078s (22% faster), mappings
  0.038s to 0.023s (41% faster). Artifacts and stdout are byte-identical on all corpus inputs.
- The kernel manifest now records which uniform slots are used as read and write bases, and the
  runtime transfers only what each direction needs: uploads cover read ranges, readbacks cover
  written ranges. Measured on the same artifacts with the old and new runtime alternating: the
  horner32 kernel drops from 0.564ms to 0.445ms (-21%), horner40 0.449ms to 0.400ms (-11%),
  poly64 0.482ms to 0.448ms (-7%). Manifests without the new fields keep the old conservative
  behaviour, so existing artifacts are unaffected.
- `compile` normalizes once and expands only the functions it will rewrite, so a second full
  expansion is gone and `rewritten.wasm` no longer re-encodes every function body: the Draco
  decoder's rewritten module drops from 754080 to 458907 bytes. Compile time: Draco 0.199s to
  0.137s, Basis 0.149s to 0.097s.
- A binary input is parsed directly instead of being disassembled to WAT and parsed back;
  this also makes `original.wasm` byte-identical to a binary input. Text (`.wat`) inputs
  are unchanged.
- `compile` prints a breakdown of why loops stayed on the CPU: side-effecting operators,
  legality split by obligation, the cost gate, lowering, and loops without an exit.
- `compile --require-offload` exits non-zero when no loop was emitted.
- `analyze --json` gains `summary.cpu_reasons`, counting CPU loops by the obligation that
  decided them (`proven_illegal` and `unknown`, per obligation kind).
- `analyze` prints the same breakdown as "why the rest stays on the CPU".
- Added Horner bodies with 24 and 40 multiplies; README now has a measured table for both
  gates (32 multiplies at compile time, 65536 trips at run time).

## 0.1.0

Source release. No published binary. The GPU path is measured on Apple M2 / Metal only.

A loop is rewritten onto the GPU only when both of these hold:

- the shader contains at least 32 multiplies
- the trip count is at least 65536

Otherwise the original Wasm runs on the CPU. Correctness is checked before a speedup is
reported. If the memories differ, `bench` does not print a ratio.

Measured with `--repeat 5`, memory restored before each timed call, output at byte 0,
input at byte 524288, `n = 65536`:

| Workload | CPU | GPU | Verdict |
| --- | --- | --- | --- |
| 16-step Horner | 0.3300 ms | 0.4753 ms | 1.44× slower, not offloaded |
| 32-step Horner | 0.9389 ms | 0.5267 ms | 1.78× faster |
| degree-64 polynomial | 3.1786 ms | 0.5832 ms | 5.45× faster |

Ratios move between runs. Those three verdicts did not.

Not in this release: floating-point operators, reductions, gathers, a Vulkan or DX12
measurement, and a real decoder call that is faster than the CPU.
